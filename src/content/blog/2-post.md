# 前言

我的大一生活我认为可以直接分成三阶段

# 初入浙工大

通过技术大作业免笔试以及连夜拷打ai通过面试，我成功进入了精弘技术部

这一阶段是我大一为数不多学习后端的时间，由Java转入golang

# 接触嵌入式

由于我是信息学院的，开学没多久就接触了智能车并决定要参加智能车比赛。学习智能车很快占据了我为数不多会拿去学习的时间（我知道错了，我再也不在宿舍躺尸啥也不学了QwQ）

我学习嵌入式可以分成两条线来讲，一条是比赛线，一条是复刻简易项目

先讲让人开心点的吧

我跟着网上复刻了一个小型桌面机器人项目，大概样子就是一只四条腿的蜘蛛模样（暂时没在手边，所以无图）。在cv完开源项目的建模和电路板后，我开始为它写驱动，控制和行为逻辑。写的过程还是挺曲折的，出现问题要排查是代码原因还是板子或者外设哪里坏了，以及写代码中频繁的修改让我意识到了⑩山是如何诞生的以及确立框架和解耦的重要性。因为是自制项目，所以在意识到问题后我毫无负担地马上开启了重构，重新设计我的代码。最后也是成功完成一只四条腿走路的蜘蛛，有表情和基础的指令行动模板以及不太好使的语音模块()

再讲不太顺利的智能车

一开始是新生赛的四轮小车，简单的驱动与基础pid应用（实际上不用pid光靠状态也能顺利完赛），这位一号小车一开始还是比较顺利的，也成功在寒假完工走完了自制赛道。由于褚老师在群里的建议以及我自己的兴趣想法，我并没有完善我的一号小车就直接转向了二号平衡车。由于当时对IIC通信并没有一个彻底的理解，导致我的平衡传感器一直无法正常传数据到我的mcu，以及当时对硬件学习较浅，硬件特别容易坏我排查问题找出坏掉的部分也十分的低效率，耽搁了大量时间。按理说，新生赛在即我应该放下有阻碍的平衡车去完善我的一号车，但是很显然，我当时可以说是比较蠢地硬是拖到了比赛前一周不到才选择放弃平衡车。于是，接下来就是几天熬夜去重启调试我的一号车，这时我才发现它在标准赛道上表现并不好，在朋友的陪伴下折腾了一两天时间（实际上，我只在半夜才去调车），终于发现了我的灰度传感器是坏的（从买来到手就是坏的，我才发现😓），此时距离新生赛只有两天（？）的时间了，于是在朋友给了我一个传感器并陪我熬了几个大夜去重调后勉强完赛了（朋友的大恩大德www）

接下来是更痛苦的省赛备赛，一直持续到了大一下学期末

具体的细节不想讲，总之最后的结论我是真不适合智能车比赛

### 算是一个小反思和复盘

首先，至少以我当时的状态我不适合当队长，一是跟硬件队友不熟，我秉持着充分相信的心态，在进度落后的情况下没有去催进度，也没有去确认硬件的完成状态。二是我个人的性格问题，由于我本人面对不熟的领域会变得无比弱势，于是在对硬件保持着敬畏的态度，我并没有也做不到强势地去规划我们的方案以及及时指出问题。

其次，我是一个受压能力非常弱以及对自己非常不自信之人。上面有说对于我个人自制的项目我能够毫无心理负担地去推翻重来，但是比赛我做不到。每次想要重构我都会害怕重构以及重构后去调试验证效果的时间最终会浪费，说不定还不如第一版，于是每次这么思考后我最后都只会在原来的⑩山上不断打补丁，造就更⑩的⑩山。（别学我www）

最后，性格使然，我没办法在公共的实验室高效地去调车以及和别的组交流经验（对不起我是社恐），我在实验室调车也是尽量选在半夜人少的时候挑一个角落去调，导致我没能及时发现小车在实验室的一段赛道上识别有问题（其实还是不重构的原因，⑩山⑩到最后终于崩了😓）。说到底我还是更适合在无人会看到的私人空间自己研究。详情可见我自己一个人调车与旁边有甚至一个人时调车的状态对比。

最后也是狠狠lose校赛了。不过还是感谢智能车路上帮助过我的朋友以及学长学姐，特别是黑白，坦白说帮了我很多也教了我不少东西。

总结：经过我校赛lose后的复盘（其实就是破防了）以及写下这篇博客时的最终check，我再也不要打智能车比赛了！！！还是自己偷摸做点小项目吧，，，

# 重回开发，面试滑铁卢

首先申明，虽然我后面基本心思都放到了智能车上，但从来没能下定决心坚定地放弃计算机。这可能也是我两边都没做好的原因之一，在选项中摇摆不定，分散心力是不好的，做人还是要专一。

部长团面试对我来说可以是一个不想回忆的时刻了，在入部后大一一整年都没有静下心去学习go语言，以及对新技术漠不关心，面试问了关于go和vibecoding的我屁都没答出来（讲个笑话，go语言中连接不同结构体的做法是继承😓）

最后面试还是进了的只是过程中狠狠破防以及一些不愉快的事发生。

# 还是说点开心的来结尾吧

大一还是认识了不少朋友，产生了不少开心的瞬间的，很多新奇的体验，新的感受。在我看来，对于我单调的十几年生活大一可以说是最丰富开心的一年了，想学什么就去学什么。遇见的大家也都是很好的人啊，我很喜欢大家的O.O
